# Build Prompt: ESV Memorize App

Feed this file to an LLM to reproduce the app from scratch. Self-contained — you need a working dir with Python 3, Node 18+, a local ESV plain-text file (one verse per line, 31,103 lines, canonical Protestant order — typically obtained legitimately from a licensed digital ESV product), and (for the public-deployment path) a free ESV API token from `api.esv.org`.

---

## Goal

Build a single-page static web app that helps an English reader memorize Bible verses from the **English Standard Version (ESV)** using **Leitner-box spaced repetition**, organized as a **12-month memorization curriculum**. The app must run **fully offline when a local `esv.json` bundle is present**, and **gracefully fall back to the Crossway ESV API** (with user-provided token) when no bundle is available.

Features:

- **Drill**: word-level masked-text fill-in with self-grading.
- **Verify**: voice-recognition verification (en-US speech recognition + LCS word diff).
- **Browse**: pick verses from the full 66-book canon — three modes (reference / search / book picker), all bundle-driven.
- **My List**: all-verses overview grouped by month.
- **Settings**: voice selection, OpenAI cloud TTS (optional), ESV API token (optional fallback).
- **Active-month filter** across drill / verify / list (defaults to current calendar month).
- **Export / import** progress as JSON.
- **TTS**: browser English voice (en-US/en-GB strict) or OpenAI cloud TTS.

All UI in English. Verse text is **never bundled in source files** that are committed to a public repo — see the Copyright section below.

---

## Tech stack

- **Frontend**: a single `index.html` (HTML + CSS + JS, no framework, no build step) + `verses.js` (12-month plan, references only) + optional `esv.json` (the full bundled text, gitignored).
- **Build script**: Python 3, no third-party deps. One script: `build/parse_esv.py` (local ESV text → esv.json).
- **Deployment**:
  - **Public path**: GitHub Pages, public repo (e.g. `bible-memorize/esv`), runs in API-fallback mode for visitors.
  - **Offline path**: same code, but with `esv.json` placed in the app folder locally. Repo stays public; bundle stays local.
- **No backend.** All state lives in browser `localStorage`. OpenAI key (if used) and ESV API token (if used) stay client-side only.

## Copyright and IP — critical constraints

The ESV is copyrighted by **Crossway**. Crossway's free-use grant permits:

- Up to **1,000 verses** in written/visual/electronic form, *or* **250 verses** in audio media, without express written permission, **provided** the quoted verses do not amount to a complete book of the Bible and do not exceed 50% of the host work.
- Use of "ESV" and "English Standard Version" trademarks requires Crossway's permission.

This app navigates the constraint by separating **source code** (committable to a public repo) from **bundled biblical text** (never committed):

| | In public repo? | Where it lives | Why |
|---|---|---|---|
| `index.html`, `verses.js`, `parse_esv.py`, `PROMPT.md`, `.gitignore` | ✓ | Repo + Pages deploy | No ESV verse text; just refs, structure, app code |
| `esv.json` (31,103 verses) | ✗ (gitignored) | Local-only on the user's machine | Bundling would redistribute the entire ESV |

**The build script (`parse_esv.py`) processes a local text file the user already legitimately owns** (typically `Esv.txt` from a licensed digital ESV product the user has access to). The script never reaches out to download the ESV text — that's the user's responsibility. The script's output (`esv.json`) is also user-local and never pushed.

When the public-deployed app runs, it falls back to the **Crossway ESV API** (`api.esv.org`) — fetching verse text at runtime per visitor's free token. This is the only legitimate way for a public deploy to expose ESV text.

## Data preparation: local ESV text → `esv.json` (`build/parse_esv.py`)

### Input

The user provides a local plain-text file with **exactly 31,103 lines, one verse per line, in canonical Protestant order** (Gen 1:1 first, Rev 22:21 last). This is the format shipped by some legitimately-owned digital ESV products. Example path: `raw/06-book/Bible/ESV/Esv.txt`.

If extraction fails (encrypted, image-only PDF, etc.), prompt the user to obtain or produce a clean plain-text file by other legitimate means.

### Encoding

Try `utf-8`, fall back to `cp1252`, last resort `latin-1` with `errors="replace"`. Some legacy ESV text dumps use Windows-1252 for special characters (em-dash `—` = 0x97).

### Canonical structure (verses per chapter)

The script must embed the **canonical Protestant verse-per-chapter table** (1,189 chapters totaling exactly 31,103 verses after ESV adjustment). This is reference data — public, not copyrightable.

Derivation: start from a well-maintained public KJV structure (e.g. `aruljohn/Bible-kjv`, which totals 31,102) and apply one ESV-specific adjustment:

> **3 John has 15 verses in ESV** (vs 14 in KJV). The +1 brings the total to 31,103, matching standard ESV plain-text dumps.

Verify the sum at script startup:
```python
total = sum(sum(b) for b in VPC)
assert total == 31103, f"VPC total {total} != 31103"
```

## Application requirements

### Storage keys (localStorage)

```
esv-memorize-progress-v1     → { "<ref>": { box: 0..4, lastReviewed: ISO } }
esv-memorize-custom-v1       → [{ ref }, ...]   user-added via Browse (no text — resolved from bundle)
esv-memorize-text-cache-v1   → { "<ref>": "...text..." }   verses fetched from the ESV API
esv-memorize-settings-v1     → { voiceURI, rate, pitch, esvApiKey, openai: { enabled, apiKey, voice, model } }
esv-memorize-month-v1        → "all" | "1".."12"   active-month filter
```

### Bundle-first dispatch architecture

```
textFor(ref)  =  bundledTexts[ref]  ||  textCache[ref]  ||  null
fetchVerse(ref) →  bundledTexts[ref]  (no network) — else textCache[ref] — else API call (requires key)
```

`bundledTexts` is populated **on app startup** by fetching `esv.json` once. If 404 (no local bundle), the app silently falls through to API-only mode.

In addition, build at load time:
- `bundledByBook` — `Map<book_slug, { en, abbr, testament, chapters: Map<int, Map<int, text>> }>`
- `bundledBooks` — array of book metadata in canonical order
- `bundledAliasMap` — lazy-built lowercased map of "jn" → "Joh", "matt" → "Mat", "1 pet" → "1Pe", etc.

The alias map must include every book's `abbr`, full English name, slug, **and** common alternative abbreviations (e.g., for John: `jn`, `jhn`, `john`; for 1 Peter: `1p`, `1pet`, `1 pet`; for Psalms: `ps`, `psalm`, `psalms`, `pss`). Build it once on first call to `parseEsvRef`.

### `parseEsvRef(s)` — reference parser

Parse a user input string like "John 3:16" / "1 Pet 2:21" / "Matt 5:3" into a canonical ref. Regex:

```
^([A-Za-z0-9 ]+?)\s*(\d{1,3})\s*[:.]?\s*(\d{1,3})$
```

Lowercase the book portion, look up in `bundledAliasMap` → slug. Then look up `bundledByBook.get(slug).chapters.get(chapter).get(verse)`. Return `{ref, text, book, chapter, verse}` or `null`.

### Top navigation

Five tabs: **Drill** | **Verify** | **Browse** | **My List** | **Settings**

Header stats: `Mo. <N> · Due <N> · Total <N> · Mastered <N>` (the month prefix omitted when active month = "all").

Footer: `Export` | `Import` (file picker) | `Clear progress` (with confirm).

### Active-month filter

Default = current calendar month, or `"all"` if the current month has zero verses. A 📅 selector bar renders above the card in Drill / Verify / My List (NOT Browse / Settings). Selection persists in `MONTH_KEY`.

### View 1 — Drill (word-level masked-text)

- All verses = seed `window.VERSES` ∪ `customVerses`, deduped by `ref`.
- Queue = `activeVerses().filter(v => isDue(v.ref) && textFor(v.ref))`.
- Due: `now - lastReviewed >= INTERVALS[box]` days.
- **INTERVALS = `[0, 1, 3, 7, 15]` days. MAX_BOX = 4.**

**Card layout:**
- Top: `🔊 <ref> · Box <N>`, with click-to-speak.
- Sub: small grey `Month <N> · <theme>` line.
- Body: verse text with **every 3rd word visible**, the rest masked as underscores **matching word length** (so `world` becomes `_____`). Punctuation always visible.
- Controls before reveal: `[Hint]` (reveal one random masked word) `[Show answer]` `[Skip]`.
- After **Show answer**: `[Got it — green]` (box+1) | `[Forgot — red]` (box=0).
- Box distribution bar at bottom.

**Tokenization for masking:**
```js
text.match(/[A-Za-z0-9']+|[^A-Za-z0-9'\s]+|\s+/g)
```
Words are runs of letters/digits/apostrophes; everything else is punctuation/whitespace. Mask only word tokens. Replace letters/digits with `_` keeping apostrophes (so `don't` becomes `___'_`).

### View 2 — Verify (voice-recognition)

Uses `SpeechRecognition` / `webkitSpeechRecognition` with `lang="en-US"`, `continuous=true`, `interimResults=true`. Pulls from `activeVerses()` queue.

**State machine — 4 phases:**

1. **ready** — `<ref> · Box <N>` + theme line + **3-word hint**: `"<first-3-normalized-words>…"`. Subtext "Recite the verse from memory." Buttons: `💭 Show verse` | `🎤 Start recording (primary)` | `Skip`.
2. **preview** — full verse text + buttons: `🎤 Start recording` | `Back`.
3. **listening** — live transcript (interim + final). Button: `🛑 Done`.
4. **result** — diff + stats + `Pass / Fail / Retry`.

**Comparison** (`compareVerse(canonical, spoken)`):
1. Normalize both: lowercase, strip non-`[a-z0-9'\s]`, split on whitespace.
2. Run **LCS-based alignment** on the word arrays. Ops: `match` / `missing` / `extra`.
3. Stats: `total = canonical word count`, `matched = count of matches`, `accuracy = matched/total`, `extras = words said but not in canonical`.

**Result rendering:**
- Big stat: `✓ X / Y words correct (Z%)` green if Z ≥ 80, else `✗ ...` red.
- Canonical verse rendered word-by-word: green if matched, red+bold if missed.
- Sub-block: Verse / You said / Extra words.
- Actions: `Pass` (box+1) | `Fail` (box=0) | `Retry` (back to ready).

**Resource lifecycle:** abort active recognition when navigating away from Verify (`setView` cleanup). `rec.onend` → `finalizeExamListening()` guarded by phase check.

### View 3 — Browse (3 bundle-driven modes)

- **Reference** — text input → live `parseEsvRef` lookup → `Add` button.
- **Search text** — substring search across all `bundledTexts` values, case-insensitive, cap 50 results, 150 ms debounce.
- **By book** — OT / NT grid of `abbr` buttons → chapter grid → verse list with `Add` per row.

`Add` writes `{ ref }` (no text — already in `bundledTexts`) to `customVerses`. The button becomes `Added` (green) once in the list.

**Empty-bundle state:** if `bundledLoaded === false`, the Browse view shows only an instruction to run `parse_esv.py`. The API-fetch path is reserved for fallback in `fetchVerse` for known refs from the 12-month plan; ad-hoc browse without a bundle is intentionally not supported (would hit the API once per keystroke).

### View 4 — My List

All verses grouped by month with section headers. For each verse: `<ref> · Box <N> · Due/—`, verse body (or `(not downloaded)` if neither bundle nor API has it), and `Remove` button (custom verses) or `seed` tag (curriculum verses).

### View 5 — Settings

**Section A — ESV text source (top, prominent)**
- If bundle loaded → green-bordered card: "Local bundle ✓ · 31,103 verses". States that the bundle stays gitignored under Crossway's license.
- If no bundle → red-bordered card: "No bundle. Run `python3 build/parse_esv.py` or add an API token below."

**Section B — ESV API token (collapsed `<details>`, optional fallback)**
- Password input for token (`Token <key>` Authorization header).
- "Fetch all 12-month verses via API" button (disabled when bundle is loaded).
- "Clear API cache" (red border).

**Section C — Browser voice**
- Dropdown filtered to `en-US` / `en-GB` / any `en-*` voices.
- Sliders: Rate (0.5–1.5, default 0.9) and Pitch (0.5–1.5, default 1.0).
- 🔊 Test button (uses a generic phrase, not a Bible verse).

**Section D — OpenAI cloud TTS (optional)**
- Checkbox `Enable` + API key + voice / model dropdowns.
- 🔊 Test button.
- Dispatch: `if (settings.openai.enabled && settings.openai.apiKey) speakViaOpenAI else speakViaBrowser`.

### Export / Import

**Export**: download `esv-memorize-YYYY-MM-DD.json`:
```json
{ "progress": {...}, "customVerses": [...], "textCache": {...}, "exportedAt": "<ISO>", "version": 1 }
```

**Import**: file picker → merge `progress` (max box wins; ties broken by latest `lastReviewed`); dedupe `customVerses` by ref; merge `textCache`.

### Reset

`Clear progress` footer link — wipes `PROGRESS_KEY` and `CUSTOM_KEY`. Preserves `SETTINGS_KEY`, `MONTH_KEY`, and `TEXT_KEY` (cached API results stay since they're expensive to refetch).

## ESV API (Crossway) — fallback only

When the bundle is absent for a given ref, the app calls:

```
GET https://api.esv.org/v3/passage/text/
Authorization: Token <user-supplied-key>
Params:
  q                                = <ref>
  include-passage-references       = false
  include-verse-numbers            = false
  include-footnotes                = false
  include-headings                 = false
  include-short-copyright          = false
  include-first-verse-numbers      = false
```

Response: `{passages: ["...text..."], ...}`. Store the trimmed text in `textCache[ref]` and persist.

Errors:
- HTTP 401 → invalid token, surface to user.
- HTTP 429 → rate limit (free tier ~5,000 queries/day).
- Other → display body for debugging.

CORS-friendly endpoint, no proxy needed.

## OpenAI cloud TTS (optional)

For users wanting more natural English voice than the browser default:

```
POST https://api.openai.com/v1/audio/speech
Authorization: Bearer <key>
Content-Type: application/json
{
  model: "gpt-4o-mini-tts" | "tts-1-hd" | "tts-1",
  input: <verse text>,
  voice: "alloy" | "echo" | "fable" | "onyx" | "nova" | "shimmer",
  speed: clamp(settings.rate, 0.25, 4.0),
  response_format: "mp3",
  instructions: <only for gpt-4o-mini-tts: "Read this Bible verse clearly and reverently in standard American English.">
}
```

Cache the MP3 blob URL in an in-memory `Map<"voice|model|rate|text", url>`.

## Deployment

### Public path (Pages site, API-mode for visitors)

1. `cd app/memorize-esv`
2. `git init -b main`
3. Verify `.gitignore` includes `esv.json` and `__pycache__/`.
4. `git add -A && git commit -s -m "Initial commit"` (always `-s`)
5. Create a public repo (e.g. `github.com/<user>/esv`). Public URL → `https://<user>.github.io/esv/`.
6. `git remote add origin git@github.com:<user>/esv.git`
7. `git push -u origin main`
8. Repo Settings → Pages → Source: `main` / `/ (root)` → Save.

Visitors will see the red "No bundle" notice in Settings until they paste an API token. After that, the 12-month curriculum verses can be fetched via "Fetch all 12-month verses".

### Offline path (your machine, bundle-mode)

1. On your local machine, obtain a legitimate plain-text ESV file (one verse per line, 31,103 lines).
2. `python3 build/parse_esv.py` → produces `app/memorize-esv/esv.json`.
3. Run a local server: `python3 -m http.server 8766 --bind 0.0.0.0` from `app/memorize-esv/`.
4. Visit `http://127.0.0.1:8766/`. Settings should show "Local bundle ✓".

`esv.json` stays on your machine; never commit it.

### Phone access while bundled

For iPhone access on the same Wi-Fi (Mac must be awake, server running):

- Find Mac's LAN IP: `ipconfig getifaddr en0`
- iPhone Safari → `http://<mac-ip>:8766/`
- Add to Home Screen for app-like icon

## Non-goals (do NOT build)

- A backend / database.
- Multi-device sync (use Export/Import for cross-device).
- A real native iOS app (PWA via Add-to-Home-Screen is sufficient).
- Multiple Bible translations in one app (would need a separate dropdown).
- "Type the full verse" mode (deferred — Drill word-mask + Verify voice are the primaries).
- Streak counters, gamification, social.
